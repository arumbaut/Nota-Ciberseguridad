La inyección SQL de primer orden ocurre cuando la aplicación procesa la entrada del usuario desde una solicitud HTTP e incorpora la entrada en una consulta SQL de manera insegura.

La inyección SQL de segundo orden ocurre cuando la aplicación toma la entrada del usuario de una solicitud HTTP y la almacena para uso futuro. Generalmente esto se hace colocando la entrada en una base de datos, pero no se produce ninguna vulnerabilidad en el punto donde se almacenan los datos. Posteriormente, al gestionar una solicitud HTTP diferente, la aplicación recupera los datos almacenados y los incorpora a una consulta SQL de forma insegura. La inyección SQL de segundo orden a menudo ocurre en situaciones en las que los desarrolladores conocen vulnerabilidades de inyección SQL y, por lo tanto, manejan de manera segura la ubicación inicial de la entrada en la base de datos. Cuando los datos se procesan posteriormente, se consideran seguros, ya que previamente se colocaron en la base de datos de forma segura. En este punto, los datos se manejan de forma insegura, porque el desarrollador considera erróneamente que son confiables.
