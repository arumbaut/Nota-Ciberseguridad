**Buffer Overflow**
Un búfer es un área de ubicaciones de memoria adyacentes asignada a un programa o aplicación para manejar sus datos en tiempo de ejecución. El desbordamiento o sobrecarga del búfer es una vulnerabilidad común en aplicaciones o programas que aceptan más datos de los que el búfer tiene asignados. Esta vulnerabilidad permite que la aplicación exceda los límites del búfer al escribir datos y sobrescriba ubicaciones de memoria vecinas. Los atacantes explotan una vulnerabilidad de desbordamiento de búfer para inyectar código malicioso en el búfer con el fin de dañar archivos, modificar datos del programa, acceder a información crítica, escalar privilegios, obtener acceso a la terminal (shell), entre otros.


Ocurre cuando una aplicación recibe más datos de los que el búfer tiene capacidad para almacenar. Como resultado, los datos sobrescriben partes adyacentes de la memoria, lo que puede provocar:  
✅ Comportamiento inesperado del sistema.  
✅ Errores de acceso a memoria.  
✅ Bloqueos o fallos del sistema.

**Los atacantes pueden inyectar código malicioso en el búfer con el fin de:**✅ Modificar datos de programas.  
✅ Acceder a información crítica.  
✅ Obtener privilegios elevados en el sistema.  
✅ Ejecutar comandos maliciosos (como obtener acceso a una terminal o shell).

#### Types of Buffer Overflow 

#### **▪ Desbordamiento de Búfer Basado en Pila (Stack-Based Buffer Overflow)**  
==En la mayoría de las aplicaciones, se utiliza una pila (stack) para la asignación de memoria estática==. ==Se asignan bloques contiguos de memoria para una pila que almacena variables temporales creadas por una función. La pila almacena las variables en orden "Último en Entrar, Primero en Salir" (LIFO, por sus siglas en inglés). Cada vez que se llama a una función, la memoria requerida para almacenar las variables se declara en la pila, y cuando la función termina, la memoria se libera automáticamente.==

**Existen dos operaciones en la pila**:
- **PUSH**: almacena datos en la pila    
- **POP**: elimina datos de la pila

**La memoria de la pila incluye cinco tipos de registros:**

- **EBP (Extended Base Pointer)**: también conocido como StackBase, almacena la dirección del primer elemento de datos guardado en la pila    
- **ESP (Extended Stack Pointer)**: almacena la dirección del siguiente elemento de datos que se almacenará en la pila    
- **EIP (Extended Instruction Pointer)**: almacena la dirección de la siguiente instrucción que se va a ejecutar
- **ESI (Extended Source Index)**: mantiene el índice fuente para diversas operaciones con cadenas    
- **EDI (Extended Destination Index)**: mantiene el índice de destino para diversas operaciones con cadenas
    
Un desbordamiento de búfer basado en pila ocurre cuando una aplicación escribe más datos en un búfer de los que realmente se asignaron para ese búfer.  
==Para entender el desbordamiento de búfer basado en pila, se debe prestar especial atención a los registros **EBP**, **EIP** y **ESP**.==  
**EIP** es el registro de solo lectura más importante, ya que almacena la dirección de la instrucción que debe ejecutarse a continuación.

#### **▪ Heap-Based Buffer Overflow**
Un heap se utiliza para la asignación dinámica de memoria. La memoria del heap se asigna dinámicamente en tiempo de ejecución durante la ejecución del programa y almacena los datos del programa. El acceso a la memoria del heap es más lento que el acceso a la memoria de la pila (stack). La asignación y liberación de la memoria del heap no se realiza automáticamente. Los programadores deben escribir código para la asignación [malloc()] de memoria en el heap y, una vez finalizada la ejecución, deben liberar la memoria usando funciones como free().
==El desbordamiento basado en heap ocurre cuando se asigna un bloque de memoria al heap y se escribe datos sin verificar los límites. Esta vulnerabilidad puede causar la sobreescritura de enlaces a asignación dinámica de memoria (punteros a objetos dinámicos), encabezados del heap, datos basados en heap, tablas de funciones virtuales, entre otros==. A diferencia de los desbordamientos de pila, los desbordamientos en heap son inconsistentes y tienen técnicas de explotación variadas.

#### La explotación de una vulnerabilidad de desbordamiento de búfer en sistemas Windows implica los siguientes pasos:

**▪ Realizar spiking**  : El spiking permite a los atacantes enviar paquetes TCP o UDP diseñados específicamente al servidor vulnerable para hacerlo colapsar.

**▪ Realizar fuzzing** : Se utiliza fuzzing para enviar una gran cantidad de datos al servidor objetivo, de modo que este experimente un desbordamiento de búfer y sobrescriba el registro EIP. Ayuda a identificar la cantidad de bytes necesarios para hacer que el servidor objetivo colapse. 

**▪ Identificar el offset**  : Los atacantes utilizan las herramientas pattern_create y pattern_offset del framework Metasploit (Ruby) para identificar: El offset (desplazamiento) exacto

**▪ Sobrescribir el registro EIP**  
**▪ Identificar caracteres problemáticos (bad characters)**  
**▪ Identificar el módulo correcto**  
**▪ Generar shellcode**  
**▪ Obtener acceso root (privilegios administrativos)**

#### Heap Spraying 
La técnica de heap spraying consiste en saturar el espacio libre del heap de memoria de un proceso objetivo escribiendo múltiples copias de código malicioso en ubicaciones específicas de memoria, explotando vulnerabilidades basadas en memoria como los desbordamientos de buffer. Los atacantes utilizan esta técnica para evadir los mecanismos de seguridad ASLR y DEP y ejecutar código arbitrario en el sistema objetivo. Al saturar el heap de memoria con copias de su payload, aumentan la probabilidad de que su código malicioso sea ejecutado en el programa o aplicación vulnerable.
#### JIT Spraying 
Los atacantes utilizan técnicas de JIT spraying (Just-In-Time spraying) para ejecutar código arbitrario en el sistema de la víctima aprovechando vulnerabilidades en la función de compilación JIT presente en muchos navegadores web modernos. En este ataque, el atacante crea código JavaScript especialmente diseñado que contiene un payload malicioso y fuerza al navegador objetivo a ejecutar ese código JavaScript. Como resultado, el compilador JIT genera dinámicamente el código máquina equivalente al JavaScript.

#### Buffer Overflow Detection Tools
▪ OllyDbg  
Fuente: [https://www.ollydbg.de](https://www.ollydbg.de)  
OllyDbg es un depurador a nivel de ensamblador de 32 bits para Microsoft® Windows®. Su énfasis en el análisis de código binario lo hace especialmente útil cuando el código fuente no está disponible. Depura aplicaciones multihilo y se puede adjuntar a programas en ejecución. Reconoce construcciones de código complejas, como llamadas o saltos a procedimientos. Realiza un seguimiento dinámico de los marcos de pila y la ejecución del programa, y registra los argumentos de funciones conocidas.
