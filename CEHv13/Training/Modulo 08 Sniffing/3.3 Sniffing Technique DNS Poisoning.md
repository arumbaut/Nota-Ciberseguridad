**DNS Poisoning Techniques**

==El envenenamiento de DNS, también conocido como DNS Spoofing, es un ataque cibernético en el que **el atacante manipula la tabla de DNS para redirigir a los usuarios a un servidor malicioso en lugar de al servidor legítimo**. En un ataque de envenenamiento de DNS, el atacante explota una vulnerabilidad en el servidor DNS o su caché.El atacante envía respuestas de DNS maliciosas al servidor DNS objetivo, haciéndole creer que las respuestas son legítimas.Estas respuestas envenenadas de DNS reemplazan las entradas correctas de direcciones IP para un dominio por la dirección IP de un servidor controlado por el atacante.==

Cuando la víctima intenta acceder a un sitio web legítimo, su sistema consulta al servidor DNS, pero debido a la tabla de DNS envenenada, se redirige al servidor del atacante.

**Defensas Contra el Envenenamiento de DNS:**

DNSSEC (Extensiones de Seguridad de DNS): DNSSEC añade una capa de seguridad mediante el uso de firmas criptográficas para verificar la autenticidad de las respuestas de DNS. Esto garantiza que los datos recibidos de un servidor DNS no hayan sido manipulados.

#### **▪ Intranet DNS Spoofing**

2-La víctima hace una solicitud DNS
3-El atacante responde antes que el servidor DNS real
4-La víctima se conecta al servidor del atacante:

#### **▪ Internet DNS Spoofing**

==Spoofing de DNS en Internet (también conocido como envenenamiento remoto de DNS) es un ataque en el que un atacante manipula las respuestas DNS de un sistema para redirigir el tráfico hacia un servidor controlado por él.==  

1-El atacante configura un servidor DNS falso con una dirección IP estática
2-Cuando la víctima se conecta a Internet, el atacante, con la ayuda de un troyano o software malicioso, se coloca entre la víctima y el servidor DNS legítimo.
3-El atacante modifica las configuraciones del DNS primario de la víctima, cambiando la IP legítima del servidor DNS por una dirección IP falsa que apunta al sistema controlado por él.
4-Cuando la víctima intenta acceder a cualquier página web, el tráfico de su solicitud DNS es redirigido al servidor del atacante en lugar de al servidor legítimo del sitio web al que quería acceder.

#### **Proxy Server DNS Poisoning**

Es un ataque en el que el atacante manipula las configuraciones del servidor proxy para redirigir el tráfico de la víctima hacia sitios web maliciosos controlados por el atacante.

1-El atacante instala un servidor proxy en su propio sistema y configura un DNS fraudulento.
2-Utiliza un troyano o software malicioso para cambiar la configuración del servidor proxy en la computadora de la víctima.
3-Cuando la víctima intenta acceder a un sitio web, el servidor proxy malicioso redirige el tráfico hacia una página falsa, diseñada para robar información confidencial

#### **DNS Cache Poisoning**

El atacante envía respuestas DNS maliciosas al servidor DNS, que están diseñadas para agregar entradas falsas a la memoria caché. Estas respuestas pueden contener direcciones IP incorrectas que apuntan a un servidor malicioso controlado por el atacante

Cuando un usuario realiza una solicitud DNS , el servidor DNS primero verifica su caché para ver si ya tiene la dirección IP asociada al dominio solicitado. Si encuentra una entrada en caché, la utiliza para responder rápidamente. En el caso del ataque, el servidor DNS devuelve la dirección IP falsa (la que ha sido envenenada), redirigiendo al usuario a un sitio web malicioso, en lugar del sitio legítimo.

#### **SAD DNS Attack**

El atacante intenta inyectar registros DNS maliciosos en la caché de un servidor DNS. Esto hace que las consultas DNS legítimas se redirijan a servidores controlados por el atacante. El objetivo principal de un ataque SAD DNS es engañar a los navegadores de los clientes para que visiten sitios web falsificados o maliciosos, en lugar de los sitios legítimos que deberían visitar

**How to Defend Against DNS Spoofing**

▪ Implement Domain Name System Security Extensions (DNSSEC).
▪ Use a Secure Socket Layer (SSL) for securing the traffic.
▪ Resolve all DNS queries to a local DNS server.
▪ Block DNS requests to external servers.
▪ Configure a firewall to restrict external DNS lookup.
▪ Implement an intrusion detection system (IDS) and deploy it correctly.
▪ Configure the DNS resolver to use a new random source port for each outgoing query.
▪ Restrict the DNS recusing service, full or partial, to authorized users.
